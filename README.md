# UXR Expert Resume

一个面向**资深 / 专家级用户研究员（Senior UXR / User Research Expert）**的简历诊断与改写 Skill。

它不是把简历“写得更高级”，而是帮助候选人从真实项目中识别并呈现：**研究判断、决策影响、落地结果与组织价值**。

> **最终目标是“可信的专家级证据”，而不是“看起来像专家”。**

## 🚀 Quick Start｜第一次使用从这里开始

如果你只是想马上开始，不需要先读完整个 README。

### 第 1 步：获取 Skill

打开仓库中的 [`SKILL.md`](./SKILL.md)，下载文件，或复制其中的完整内容。

### 第 2 步：加载到你使用的 AI

你可以选择其中一种方式：

- 如果你的 AI 工具支持自定义 Skill / Agent / Instructions：将 `SKILL.md` 作为规则加载。
- 如果不支持：在新对话中上传 `SKILL.md`，明确告诉 AI **“请按照这个 Skill 与我一起修改简历”**。
- 也可以直接复制 `SKILL.md` 全文作为系统指令 / 长提示词使用。

不同 AI 产品的 Skill 加载方式可能不同；这个项目本身不依赖某一个特定 AI 产品。

### 第 3 步：根据你的情况选择一句开场白

**A. 我已经有完整简历**

```text
我要应聘用户研究专家，这是我的现有简历。
请按照这个 Skill 的流程先诊断，不要直接重写。
```

**B. 我还没有整理简历**

```text
我有 X 年用户研究经验，准备应聘用户研究专家。
我还没有整理简历，请按照这个 Skill 引导我逐步梳理职业经历和代表项目。
```

**C. 简历已经有了，但项目写得很普通**

```text
我的简历基本完整，但代表项目体现不出专家级能力。
请重点帮我筛选和深挖项目，先不要处理排版。
```

### 第 4 步：不要急着让 AI 一次性重写

理想流程是：

**目标职级 → 经历诊断 → 项目筛选 → 深挖追问 → 研究判断 → 归因确认 → 逐段改写 → 整体 QA → 排版**

如果 AI 一上来就把整份简历“润色得很高级”，可以直接提醒：

```text
先不要润色。请按照 Skill 先判断我的项目价值、个人贡献和决策影响，不清楚的地方继续问我。
```

## 为什么做这个 Skill

很多资深用户研究员拥有大量项目经验，但简历仍容易停留在：

- 做过访谈、问卷、焦点小组、可用性测试
- 负责某业务线用户研究
- 支持多个产品项目
- 输出用户洞察与研究报告

这些内容能够证明“会做研究”，却不一定能够证明为什么候选人已经达到 Senior / Expert 水平。

这个 Skill 的核心目标，是把叙事从：

> 我做过什么研究

转向：

> 我如何把模糊的业务问题转化成正确的研究问题，并通过研究判断改变业务认知或决策。

## 核心框架

### 1. 用研价值链

**业务问题 → 研究问题 → 关键研究判断 / 发现 → 决策变化 → 产品 / 策略 / 机制变化 → 上线 / 实验 / 复用 → 用户或业务结果**

简历不需要写完整条链，但应该找到真正属于候选人的关键节点。

### 2. 归因测试

始终追问：

> **如果把这个用户研究员从项目里拿掉，什么事情可能不会发生？**

这个问题用于区分“参与了项目”和“真正产生了不可替代的研究贡献”。

### 3. 用研业绩

**用研业绩 = 研究发现 × 决策影响 × 落地验证**

它是一个判断模型，而不是机械评分公式。

### 4. 数字的作用

> **数字主要证明规模，文字主要证明影响。**

项目数量、访谈数量、持续时间、团队规模可以证明工作规模，但不能替代对研究价值的解释。

## 一个简单的 Before / After

下面是一个**虚构案例**，仅用于说明这个 Skill 在寻找什么。

### Before：只有研究动作

> 针对低活用户开展访谈和问卷研究，分析用户低活原因，为产品优化提供建议。

问题不在于这句话不专业，而是它只能证明“做过研究”。招聘者仍然不知道研究员做出了什么关键判断，以及研究究竟改变了什么。

### After：呈现研究判断与业务价值

> 围绕低活人群开展研究，通过长期行为变化与用户自确认区分稳定低频与真实衰退用户，识别具有业务干预价值的重点人群，并还原用户活跃下降的关键路径，为后续策略确定问题优先级。

变化并不是简单替换几个“高级词”，而是补出了：

**业务给出的结果人群 → 重新定义真正研究对象 → 解释变化机制 → 明确干预对象 → 支持业务优先级判断。**

如果真实项目并不存在这些事实，Skill 不应该自行补写。

## 适合谁

优先适用于：

- 7 年以上用户研究经验的候选人
- Senior UXR / 用户研究专家 / 资深用户研究员
- 用户研究负责人、Research Lead
- 长期没有换工作、项目很多但不知道如何取舍的人
- 简历大量描述研究方法与“支持项目”，但专家级价值不明显的人

经验较少的研究员也可以使用，但不必强求组织影响、机制建设和战略研究经历。

## 它会怎么工作

Skill 不会拿到简历后立即大面积润色，而是先完成：

1. 确认目标岗位与职级
2. 判断职业经历的优先级
3. 区分职责、研究动作、研究判断、业务影响与落地结果
4. 筛选真正值得进入核心区域的代表项目
5. 深挖业务背景、关键研究判断、决策变化与个人贡献
6. 检查业务结果是否被过度归因给用户研究
7. 用户确认事实后再进行简历改写
8. 内容稳定后再处理视觉排版

### 你应该预期 AI 会继续问你问题

这是这个 Skill 的正常工作方式，而不是失败。

例如 AI 可能会继续问：

- 当时业务为什么要做这个研究？
- 业务最初认为问题是什么？
- 你有没有发现原来的问题定义本身不准确？
- 研究前业务准备怎么做？
- 研究之后具体改变了什么？
- 最终进入产品、策略、算法还是运营决策？
- 有没有上线、实验、推全或长期复用？
- 如果没有你，这件事情最可能有什么不同？

很多真正体现专家水平的信息，并不存在于旧简历里，而存在于你对项目的记忆和判断里。

## 特别关注的专家级证据

例如：

- 重新定义研究对象或研究问题
- 从结果指标还原用户变化的形成机制
- 识别真正具有业务干预价值的人群
- 发现功能、行为背后的场景差异
- 将用户反馈转化为数据 / 算法可使用的分类标准
- 让研究洞察进入产品、推荐策略或业务决策
- 将一次性研究升级为长期机制
- 在有限研究资源下重新设计业务协作方式
- 通过研究调整甚至否定业务原方案

## 不鼓励的写法

Skill 会主动避免：

- 用研究方法清单冒充业绩
- 为了“高级感”堆砌赋能、闭环、抓手等词汇
- 把团队或最终业务结果全部归因为用研个人成果
- 为了数字化而虚构指标
- 所有工作经历平均展开
- 为了版式统一强迫不同经历使用相同结构
- 项目事实尚未厘清就直接进行 AI 式润色

## 三种典型使用场景

### 场景 1：完整简历体检

适合已经有一版简历，但不知道是否达到专家岗位要求的人。

建议提供：**现有简历 + 目标岗位/JD**。先让 Skill 判断哪段经历最值得展开，以及当前最大的证据缺口。

### 场景 2：代表项目深挖

适合“项目很多，但写出来都像普通研究项目”的人。

一次提供 2–5 个候选项目，让 Skill 判断哪些项目更能证明研究判断、决策影响和落地能力，然后只深挖最有价值的项目。

### 场景 3：从零开始整理

适合多年没有更新简历，甚至不知道应该从哪里开始的人。

不需要先写完整简历。可以从最近一家公司开始，依次梳理：**职责范围 → 候选项目 → 强案例 → 历史经历 → 个人简介**。

## 推荐提供给 AI 的材料

不是所有材料都必须一次准备齐。优先级如下：

1. **目标岗位或 JD**：帮助判断简历应该证明什么。
2. **现有简历**：哪怕很旧也有价值。
3. **最近一段核心工作经历**：通常最值得重点打磨。
4. **2–5 个候选项目**：只需先写背景和自己记得的事实，不需要提前包装。
5. **可公开的结果信息**：上线、实验、推全、机制复用、获奖等。

涉及公司保密信息时，可以主动模糊具体业务数字、项目代号和内部信息。Skill 的目标不是逼用户披露敏感数据。

## FAQ

### Q1：一定要有 7 年经验才能用吗？

不是。7 年以上只是这个 Skill 最主要的目标人群。经验较少的研究员也可以使用，但不应该为了“专家感”强行寻找并不存在的战略或组织影响。

### Q2：我没有明确的业务增长数字，还能写出好简历吗？

可以。用户研究的价值不等于最终业务指标。研究是否改变决策、推动具体方案、进入实验、完成上线或形成长期复用，本身都是重要证据。

### Q3：我的项目涉及保密数据怎么办？

不要为了简历完整而披露敏感信息。可以使用“实验取得正向收益”“完成推全”“进入后续策略优化”等能够证明验证程度、但不暴露具体内部指标的表达。

### Q4：可以直接让 AI 输出最终简历吗？

可以，但不推荐作为第一步。这个 Skill 的价值主要发生在“追问和判断”阶段。项目事实越充分，最终文字越可信。

### Q5：为什么 AI 一直问我问题，而不是直接改？

因为很多高级能力隐藏在项目细节中。直接改旧文字通常只能得到更漂亮的旧叙事；追问是为了找到原简历没有写出来的研究判断和影响。

### Q6：这个 Skill 能保证我拿到面试吗？

不能。它帮助改善简历中的证据组织、项目归因和表达方式，但招聘结果还受到岗位匹配、经历、市场、面试表现等多种因素影响。

### Q7：它只适合中文简历吗？

目前核心方法不依赖语言，但当前规则和示例主要围绕中文互联网用户研究岗位设计。英文简历可以使用同一判断框架，再根据英文招聘语境调整表达。

## 使用原则

如果你只记住一件事，请记住：

> **先判断项目价值，再优化文字。**

这个 Skill 不是替你制造一个“专家形象”，而是帮助你从真实职业经历中找到足以证明专家水平的证据。
